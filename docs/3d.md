# 3D models, 3D Tiles, I3S and point clouds: `mbt-map/3d`

`mbt-map/3d` adds 3D content to a map as custom layers, which you add with `map.addLayer`. It provides four layers: `modelLayer` places a glTF model at GeoJSON points, `tilesLayer` streams OGC 3D Tiles (such as PLATEAU's city models), `i3sLayer` streams I3S scene layers and SLPK packages, and `pointCloudLayer` draws a LAS file. Parsing and decoding (glTF, Draco, meshopt, LEPCC, LAS) run in a 3D worker with its own wasm, started by the first layer. The layers draw on Web Mercator and on the globe, share the depth buffer with fill-extrusions and terrain, cast and receive shadows, and follow the map's clipping. The entry point also has two measurement helpers for 3D scenes, `lineOfSight` and `measure3d`. Picking, ray casting, viewsheds, clipping and lights are `Map` methods documented in [map.md](./map.md).

```js
import { Map } from "mbt-map";
import { tilesLayer } from "mbt-map/3d";

const map = new Map({ container: "map", style, center: [139.7671, 35.6812], zoom: 16.5, pitch: 60 });
const buildings = tilesLayer({ id: "plateau", url: "https://example.com/tileset.json", height: -36.7 });
map.once("load").then(() => map.addLayer(buildings));
```

All four layers are custom layers with `renderingMode: "3d"`. Like other custom layers, a new style set with `setStyle` drops them, so add them again on `styledata` if your page swaps styles (see [map.md](./map.md)).

## glTF models: `modelLayer`

```ts
modelLayer(options: ModelLayerOptions): ModelLayer
loadModel(url: string | URL, options?: ModelOptions): Promise<LoadedModel>
```

`modelLayer` draws one glTF 2.0 model at each point of `data`.

| Option | Meaning | Default |
|---|---|---|
| `id` | The layer id. | required |
| `model` | A URL of a `.glb`, or of a `.gltf` with its buffers and images beside it, or a model returned by `loadModel` (to share one model between layers). | required |
| `data` | A GeoJSON Point, Feature or FeatureCollection. A third coordinate is the height in meters. | required |
| `scale` | `[x, y, z]` | `[1, 1, 1]` |
| `rotation` | `[x, y, z]` degrees about the east, north and up axes. z turns the model clockwise seen from above. | `[0, 0, 0]` |
| `translation` | `[east, north, up]` meters | `[0, 0, 0]` |
| `opacity` | 0 to 1 | 1 |
| `hemisphere` | A hemisphere light, see [Lighting](#lighting) below. | 1 (none) |
| `workerUrl`, `wasmUrl` | Where `3d-worker.js` and `3d.wasm` are served. | next to `3d.js` |

`scale`, `rotation` and `translation` follow Mapbox's `model-scale`, `model-rotation` and `model-translation`. Each of them, and `opacity`, can be a constant or read a feature property with `["get", key]`, either as a whole or per number:

```js
import { modelLayer } from "mbt-map/3d";

const towers = {
  type: "FeatureCollection",
  features: [{ type: "Feature", properties: { heading: 30 }, geometry: { type: "Point", coordinates: [139.7643, 35.6814] } }],
};
const layer = modelLayer({ id: "towers", model: "/models/tower.glb", data: towers, rotation: [0, 0, ["get", "heading"]], scale: [2, 2, 2] });
map.addLayer(layer);
await layer.ready;            // settles once the model is loaded, or rejects with the reason
layer.setData(newTowers);     // move or add instances
```

`ModelLayer` members: `ready` (a Promise) and `setData(data)`.

**glTF support.** Models are glTF 2.0, as `.glb` or as `.gltf` with external or embedded buffers and images. The model's +Y up is turned to map up. The layer reads meshes, the node hierarchy and its matrices, sparse accessors, and materials: the base color factor and texture, the alpha modes `OPAQUE`, `MASK` and `BLEND`, and double-sided faces. These extensions are read:

| Extension | Use |
|---|---|
| `KHR_mesh_quantization` | Quantized attributes, kept quantized on the GPU. |
| `KHR_texture_transform` | Base color texture transform. |
| `KHR_materials_unlit` | Unlit materials. |
| `EXT_meshopt_compression`, `KHR_meshopt_compression` | meshopt-compressed buffer views. |
| `KHR_draco_mesh_compression` | Draco-compressed meshes and point primitives. |
| `EXT_texture_webp` | WebP textures, preferred when offered. |
| `CESIUM_RTC` | Relative-to-center positions. |
| `EXT_mesh_features`, `EXT_structural_metadata` | Feature ids and property tables, used by `queryFeature` in 3D Tiles. |

A model that requires any other extension is refused. Models are capped at 512 MB in total, the glTF JSON at 64 MB and the node tree at 64 levels.

### Lighting

Surfaces get Lambert shading from a fixed default light direction. Normals the model lacks are computed from the screen. Faces are drawn double-sided, and blended materials and translucent instances are drawn in a second pass without depth writes. When the style has `lights` (see `setLights` in [map.md](./map.md)), the layers use that ambient and directional light and its shadows.

With one directional light, every face turned away from it gets the ambient light alone, so the far side of a model is one flat color. The `hemisphere` option of `modelLayer`, `tilesLayer` and `i3sLayer` shades the ambient light to give that side its shape. It is the share of the ambient light, from 0 to 1, that a face turned straight away from the light keeps. A face turned to the light keeps all of it, and faces between are eased by the angle between their normal and the light's direction: `ambient * (1 - (1 - hemisphere) * (0.5 - 0.5 * dot(normal, light)))`. Three numbers `[r, g, b]` tint the shade, for instance toward blue. The default 1 leaves the ambient light as it is, and other values are ignored.

```js
map.addLayer(tilesLayer({ id: "city", url: "/tiles/tileset.json", hemisphere: 0.6 }));
map.addLayer(modelLayer({ id: "towers", model: "/models/tower.glb", data: towers, hemisphere: [0.5, 0.55, 0.7] }));
```

The option belongs to the layer, not to the style's `lights`, so fill-extrusion layers are not shaded by it. Unlit materials and point clouds are not either.

## 3D Tiles: `tilesLayer`

```ts
tilesLayer(options: TilesLayerOptions): TilesLayer
```

`tilesLayer` streams a 3D Tiles 1.0 or 1.1 tileset from its `tileset.json`.

| Option | Meaning | Default |
|---|---|---|
| `id` | The layer id. | required |
| `url` | The tileset JSON. | required |
| `maximumScreenSpaceError` | A tile is refined while its screen-space error exceeds this. | 8 |
| `height` | Meters added to every tile. Use it to put ellipsoidal heights on the map's ground. | 0 |
| `maximumLoadedTiles` | Contents kept loaded at most. The least recently used ones are released. | 256 |
| `pointSize` | Diameter of point cloud points in CSS pixels. | 2 |
| `hemisphere` | A hemisphere light, see [Lighting](#lighting). | 1 (none) |
| `workerUrl`, `wasmUrl` | Where `3d-worker.js` and `3d.wasm` are served. | next to `3d.js` |

**Supported content:**

| Content | Notes |
|---|---|
| b3dm | Feature table (`RTC_CENTER`), batch table (JSON and binary body) and its glb. |
| i3dm | Each instance drawn with its own matrix (positions, normal up/right, oct-encoded normals, scale, RTC), with batch ids. |
| pnts | Positions (float or quantized), colors (RGBA, RGB, RGB565, `CONSTANT_RGBA`), normals (including oct-encoded), batch ids or per-point batch rows, and `3DTILES_draco_point_compression`. |
| cmpt | Inner tiles of any of these kinds, nested composites flattened. |
| glTF / glb | 3D Tiles 1.1 contents, including point primitives. |

The traversal follows the tileset's tree: `box`, `region` and `sphere` bounding volumes, tile `transform`s, `ADD` and `REPLACE` refinement, `viewerRequestVolume`, empty tiles, external tilesets and implicit tiling (quadtree and octree subtrees). Contents load in the 3D worker, six at a time, nearest first.

`TilesLayer` members:

| Member | Meaning |
|---|---|
| `ready` | Settles once the tileset JSON is read, or rejects with the reason. |
| `selected` | The tiles drawn in the last frame. Each `Tile` has a `path`, `geometricError`, `refine`, `contentUrl`, `state` and so on. |
| `idle` | Whether the last frame asked for no new content and none is loading. |
| `queryFeature(point)` | The feature at a CSS pixel of the map's canvas. See [Picking features](#picking-features). |

**Heights.** 3D Tiles heights are above the WGS 84 ellipsoid, while the map's ground is near sea level. Pass the geoid height at the area as a negative `height` so buildings stand on the ground. For example, use about -36.7 m around Tokyo Station. With terrain at exaggeration 1, tiles meet the terrain through the shared depth buffer.

```js
import { Map } from "mbt-map";
import { tilesLayer } from "mbt-map/3d";

// 3D city model: 「3D都市モデル（Project PLATEAU）千代田区（2025年度）」（国土交通省）, https://www.mlit.go.jp/plateau/
const PLATEAU = "https://assets.cms.plateau.reearth.io/assets/72/e900e5-938c-4376-a9de-a124b270880c/13101_chiyoda-ku_pref_2025_citygml_1_op_bldg_3dtiles_13101_chiyoda-ku_lod2_no_texture/tileset.json";

const map = new Map({ container: "map", style, center: [139.7671, 35.6812], zoom: 16.5, pitch: 60, bearing: -20 });
const layer = tilesLayer({ id: "plateau", url: PLATEAU, height: -36.7 });
layer.ready.catch((e) => console.error("tileset not read:", e.message));

map.once("load").then(() => map.addLayer(layer));
map.on("render", () => console.log(`${layer.selected.length} tiles${layer.idle ? "" : " (loading)"}`));
map.on("click", async (e) => {
  const hit = await layer.queryFeature(e.point);
  if (hit) console.log(hit.properties["bldg:measuredHeight"]);
});
```

## I3S and SLPK: `i3sLayer`

```ts
i3sLayer(options: I3sLayerOptions): TilesLayer
```

`i3sLayer` streams an I3S scene layer of type 3DObject, IntegratedMesh or PointCloud (I3S 1.7 and later, with node pages, in WGS 84). `url` can be:

- A SceneServer layer, for example `https://.../SceneServer/layers/0`.
- A layer document `....json` with its resources beside it.
- An `.slpk` package. Packages are read by HTTP range requests (the whole file when the server refuses ranges), using the package's hash table when present, otherwise its zip directory.

Options are those of `tilesLayer` without `maximumScreenSpaceError`: `id`, `url`, `height`, `maximumLoadedTiles`, `pointSize`, `hemisphere`, `workerUrl` and `wasmUrl`. Point cloud layers also take `color` (as in `pointCloudLayer`; heights ramp over the root node's box). The layer returned is a `TilesLayer`, with the same `ready`, `selected`, `idle` and `queryFeature`.

- Mesh nodes are chosen by their `lodThreshold`, with `maxScreenThreshold` and `maxScreenThresholdSQ` metrics. Their geometry comes from the Draco geometry buffer when offered, otherwise the uncompressed one. Textures are JPEG or PNG, and texture atlases with uv regions are supported.
- Point cloud nodes are refined by the density of their points on screen. Their LEPCC-encoded positions, RGB and intensity are decoded in the worker, and class codes are read from the attribute resources.
- `queryFeature` returns the feature's attributes, read from the node's attribute buffers and matched by OBJECTID.

```js
import { i3sLayer } from "mbt-map/3d";

const city = i3sLayer({ id: "city", url: "https://example.com/arcgis/rest/services/City/SceneServer/layers/0" });
const cloud = i3sLayer({ id: "cloud", url: "/data/survey.slpk", color: "classification", pointSize: 3 });
map.addLayer(city);
map.addLayer(cloud);
```

## LAS point clouds: `pointCloudLayer`

```ts
pointCloudLayer(options: PointCloudLayerOptions): PointCloudLayer
```

`pointCloudLayer` reads an uncompressed LAS file (versions 1.0 to 1.4, point data formats 0 to 10) in the 3D worker and draws it as one point mesh. LAZ is refused.

| Option | Meaning | Default |
|---|---|---|
| `id` | The layer id. | required |
| `url` | The `.las` file. | required |
| `crs` | The CRS of the coordinates: an EPSG code or PROJ string. Overrides the CRS stated in the file (GeoTIFF keys or WKT). | from the file |
| `maxPoints` | Thinned to at most this many points, keeping every k-th point. | 2 000 000 |
| `pointSize` | Point diameter in CSS pixels. | 2 |
| `color` | `"rgb"` (the file's colors, the default when it has them), `"height"`, `"intensity"` or `"classification"` (ASPRS classes). | `"rgb"` |
| `workerUrl`, `wasmUrl` | Where `3d-worker.js` and `3d.wasm` are served. | next to `3d.js` |

Coordinates are converted to longitude and latitude through `proj.wasm`. `crs` and the EPSG codes the file can state work as in [analysis.md](./analysis.md#coordinate-systems). Heights are used as they are in the file. Height and intensity colors use a viridis-like ramp over the points' range.

`PointCloudLayer` members:

| Member | Meaning |
|---|---|
| `ready` | Settles once the file is read, or rejects with the reason. |
| `bounds` | `[west, south, east, north]` of the points, once ready; otherwise `null`. |
| `counts` | `{ file, drawn }`: points in the file and points drawn after thinning, once ready; otherwise `null`. |
| `setColor(mode)` | Colors the points by another mode. |

```js
import { pointCloudLayer } from "mbt-map/3d";

const cloud = pointCloudLayer({ id: "scan", url: "/data/scan.las", crs: 6677, color: "height" });
map.addLayer(cloud);
await cloud.ready;
const [w, s, e, n] = cloud.bounds;
map.fitBounds([[w, s], [e, n]]);
cloud.setColor("classification");
```

## Picking features

`TilesLayer.queryFeature(point)` returns the feature drawn at a CSS pixel of the map's canvas, after the next frame:

```ts
queryFeature(point: { x: number; y: number }): Promise<TileFeature | null>
// TileFeature: { tile: string; id: number; properties: Record<string, unknown> }
```

| Field | Meaning |
|---|---|
| `tile` | The tile's `path`. |
| `id` | The feature id within the tile: the b3dm/pnts batch id, the i3dm instance's batch id, or the `EXT_mesh_features` feature id. For I3S, the node's feature index. |
| `properties` | From the batch table (JSON and binary), the `EXT_structural_metadata` property table, or the I3S attribute buffers. |

Ids above 65 535 wrap. The pick pass draws only the selected tiles, so a feature that is hidden or not loaded returns `null`. An external `schemaUri` in `EXT_structural_metadata` is not fetched.

## 3D measurement: `lineOfSight` and `measure3d`

```ts
lineOfSight(map, from: [lng, lat, m], to: [lng, lat, m], margin?: number): { visible: boolean; obstruction: [number, number, number] | null }
measure3d(points: [lng, lat, m][], { closed }?): Measure3d
```

- `lineOfSight` checks whether `to` can be seen from `from` over everything the map draws: extrusions, 3D layers and terrain. It uses `Map.castRay`, stopping `margin` meters short of `to` (default 0.1), so the surface `to` was picked on doesn't hide it. `obstruction` is the first point in the way. It runs synchronously.
- `measure3d` measures between 3D points on WGS 84, with heights in meters above the ellipsoid.

  | Field | Meaning |
  |---|---|
  | `length` | Straight-line (slant) distance along the points. |
  | `horizontal`, `vertical` | Its horizontal part, and the signed difference of the last and first heights. Each edge is taken in the east-north-up frame at its first point. |
  | `distances` | The slant distance to each point. |
  | `area`, `horizontalArea` | With `closed: true`: the ring's surface area (a facade as it is) and its footprint, in the frame at its centroid. |

Pick the points with `map.pickPosition`, which returns `[lng, lat, m]` for a screen point:

```js
import { lineOfSight, measure3d } from "mbt-map/3d";

const EYE = 1.6;
let from = null;
map.on("click", (e) => {
  const at = map.pickPosition(e.point);
  if (!at) return;
  if (!from) return void (from = [at[0], at[1], at[2] + EYE]);
  const s = lineOfSight(map, from, at);
  console.log(s.visible ? "visible" : `blocked ${measure3d([from, s.obstruction]).length.toFixed(1)} m away`);
  from = null;
});
```

[mbt-map/ui](./ui.md)'s `createMeasurement` measures in 3D when you pass it `measure3d`: `createMeasurement(map, { measure3d })`.

## Map methods for 3D scenes

These are methods of `Map` and work with extrusions as well as the layers above. See [map.md](./map.md) for their options.

| Method | Use |
|---|---|
| `pickPosition(point)` | The `[lng, lat, m]` under a screen point, on 3D content or the ground. |
| `castRay(from, to, margin?)` | The first point where a segment meets drawn geometry, or `null`. |
| `setViewshed(v)` | Tints what an observer (`position`, `heading`, `pitch`, `horizontalFov`, `verticalFov`, `distance`) sees green and what is hidden red. `null` turns it off. |
| `setClipping(c)` / `getClipping()` | Cuts the scene with planes in east-north-up meters at an `origin`, or with polygons. 3D layers follow it. |
| `setLights(lights)` / `getLights()` | Ambient and directional lights with optional shadows. The 3D layers are lit and shadowed by them. |

```js
// A vertical section across the view at a clicked point. The orange band marks the cut.
const at = map.pickPosition(point);
const b = (map.getBearing() * Math.PI) / 180;
map.setClipping({ origin: [at[0], at[1], 0], planes: [[Math.sin(b), Math.cos(b), 0, 0]], edgeWidth: 2, edgeColor: [1, 0.55, 0.1] });
```

## Files, workers and lifetime

| File | Loaded |
|---|---|
| `3d.js` | The entry point. |
| `3d-worker.js`, `3d.wasm` | With the first layer or `loadModel`. The wasm decodes meshopt, Draco and LEPCC. |
| `3d-tiles.js` | With the first `tilesLayer` or `i3sLayer`. |
| `3d-i3s.js` | With the first `i3sLayer`. |
| `3d-slpk.js` | With the first `i3sLayer` of an `.slpk`. |
| `proj.wasm`, `prjwkt.js` | By the worker, for LAS files in a projected CRS and for WKT-only LAS files. |

Every file loads from next to `3d.js` by default. `workerUrl` and `wasmUrl` in a layer's options (the first one used starts the worker) can point elsewhere. `terminate()` stops the 3D worker and rejects pending loads. See [getting-started.md](./getting-started.md) for serving the files with a bundler.
